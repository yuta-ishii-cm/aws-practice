# AWS Weekly Challenge ブログ作成ルール

blogs フォルダ内のマークダウンファイル作成時に適用するルールです。

---

## 基本情報

- **ターゲット読者**: AWS初心者
- **文体**: カジュアル（親しみやすいブログ風）
- **詳細度**: 初心者でも迷わない詳細な解説

---

## タイトル形式

```
AWS Weekly Challenge #XX ~ [カテゴリ] 概要タイトル ~
```

**例**:
- `AWS Weekly Challenge #01 ~ [Web構築編] 静的サイトをS3+CloudFrontで配信 ~`
- `AWS Weekly Challenge #05 ~ [AI活用編] BedrockでRAGチャットボット構築 ~`

---

## ファイル・フォルダ構成

```
blogs/
├── 01/
│   ├── index.md          # ブログ本文
│   └── images/           # スクリーンショット・図
│       ├── architecture.png
│       ├── step-01-xxx.png
│       └── ...
├── 02/
│   ├── index.md
│   └── images/
└── ...
```

- ファイル名: `index.md`（番号はフォルダ名で管理）
- 画像: 各記事フォルダ内の `images/` に配置
- 画像ファイル名: `step-XX-説明.png` の形式推奨

## YAML Frontmatter

各ブログの冒頭に以下のfrontmatterを含める:

```yaml
---
title: "AWS Weekly Challenge #01 ~ [Web構築編] 静的サイトをS3+CloudFrontで配信 ~"
date: 2024-01-15
category: Web構築編

  - CloudFront
  - 静的サイト
difficulty: 初級
duration: 2-3時間
services:
  - Amazon S3
  - Amazon CloudFront
  - AWS Certificate Manager
---
```

## 必須セクション構成

以下の順序でセクションを構成する:

### 1. 冒頭の挨拶

```markdown
こんにちは！製造ビジネステクノロジー部の石井です。
```

### 2. 概要・目的

- この演習で何を作るのか
- 何が学べるのか
- 完成イメージ（スクリーンショット、動画、GIFなど）

### 3. アーキテクチャ図

- 構成図（Mermaid または 画像）
- なぜこの構成なのかの説明
- 各コンポーネントの役割

### 4. コスト情報

- 発生する料金の目安
- 無料枠で収まるか
- 注意すべき課金ポイント

```markdown
**💰 コスト目安**: この構成の月額コスト目安は約$X.XX（無料枠適用後）です。
```

### 5. 前提条件・環境

- 必要な知識
- AWSアカウントの準備
- ローカル環境の要件
- 事前にインストールが必要なツール

### 6. 構築手順（メインコンテンツ）

- ステップバイステップで詳細に
- 各ステップにスクリーンショットを添付
- コードブロックはコピペ可能な形式で

### 7. 動作確認

- 構築したものが正しく動くかの確認手順
- 期待される結果のスクリーンショット

### 8. トラブルシューティング（任意）

- よくあるエラーとその解決策
- ハマりやすいポイント

### 9. クリーンアップ手順

- リソース削除の手順
- 削除し忘れると課金が続くリソースの警告

### 10. まとめ・振り返り

- 学んだことの要約
- 今回のポイント

### 11. 参考リンク

- AWS公式ドキュメント
- 関連する技術記事

## 文体・トーンのガイドライン

### 推奨する表現

- 「〜していきましょう」「〜してみます」
- 「ここがポイントです！」
- 「初心者の方でも大丈夫」
- 「実際にやってみると〜」

### 避ける表現

- 過度に堅い「〜である」調
- 専門用語の説明なしでの使用
- 「簡単です」（初心者には簡単でないかもしれない）

---

## コードブロックのルール

### 基本形式

- 言語を必ず指定する
- ファイル名がある場合はコメントで示す
- 長いコードはファイル単位で分割

```typescript
// src/handler.ts
export const handler = async (event: APIGatewayEvent) => {
  // 処理内容
};
```

### コードの前後に解説を入れる

```markdown
次に、Lambda関数のハンドラーを作成します。
このコードでは、APIリクエストを受け取って処理を行います。

[コードブロック]

`event` にはAPIリクエストの情報が含まれています。
```

## 警告・注意点の表記

Contentful互換のため「絵文字 + 太字」形式を使用:

```markdown
**📝 補足**: 補足情報やヒント

**💡 Tips**: 便利なTipsや裏技

**⚠️ 注意**: 注意が必要なポイント

**🚨 重要**: 課金や削除に関する重大な警告
```

**使い分け**:
- 📝 補足: 補足説明、豆知識
- 💡 Tips: 効率化のヒント、ショートカット
- ⚠️ 注意: エラーになりやすいポイント、見逃すと困る事項
- 🚨 重要: 課金・データ損失に関する警告

## スクリーンショットのガイドライン

- AWSコンソールの操作は必ずスクショを添付
- 重要な箇所は赤枠や矢印で強調
- 個人情報（アカウントID等）はマスク処理
- alt属性に説明を入れる

```markdown

```

## Contentful互換性について

このブログはContentfulで公開するため、以下の記法に注意:

**使用可能**:
- 見出し（#, ##, ###）
- 太字（**text**）、斜体（*text*）
- リスト（箇条書き、番号付き）
- リンク（`[text](url)`）
- コードブロック（```language）
- インラインコード（`code`）
- 画像（`![alt](path)`）
- テーブル
- 絵文字

**使用不可**:
- GitHub Admonition（`> [!WARNING]` など）
- 脚注
- タスクリスト（`- [ ]`）
